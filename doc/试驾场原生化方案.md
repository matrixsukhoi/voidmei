# 试驾场原生化完整方案 — 迁移 · 重构 · 实现

> 2026-09-12 立稿。承接 `hud编辑器全景与验证手册.md` 的试驾场形态（容器/右键/拖放/撤销/流动数据已落地），
> 本方案收最后一个口子：**编辑体验 100% 原生同栈** — webview 编辑面板全退役，MainForm 回归纯机库。
> 设计文档（心智模型）: `~/.claude/plans/overlay-fizzy-iverson.md` 的落地延续。

## 0. 目标与原则

- **一栈到底**: 真窗 HUD、右键菜单、侧栏、悬浮条、属性编辑、页面管理 — 全部 skia/Win32 原生，
  渲染线程单泵、同一份字体与调色板、同一种交互质感。编辑期 webview 零参与。
- **MainForm = 纯机库**: 全局设置/页面开关/导入导出/语音/更新。编辑期隐退，编辑职责一项不留。
- **分段可验收**: 四阶段（A 基座 → B 属性 → C 清链 → D 完整度），每段结束 workspace 全绿 + 人工验收，可独立停在任何一段。

## 2. 核心技术决策

### D1 — PanelWindow：非分层窗口类型（为什么不是继续复用 WinOverlay）

现状侧栏/悬浮条复用 `WinOverlay`（ULW 分层窗口）。两个问题：
1. **ULW 与子控件互斥**（硬约束）: `UpdateLayeredWindow` 窗口的内容完全由 ULW 表面提供，
   WS_CHILD 子控件（EDIT/COMBOBOX）不会被合成进来 — 文本输入无解。
2. **能力错配**: 侧栏/悬浮条是不透明 UI，根本不需要 per-pixel alpha（那是 HUD 悬浮在游戏画面上的需求）。

方案: `WindowConfig` 增加 `kind: WindowKind`（`Layered` = 现行 ULW，HUD 用 | `Opaque` = 普通窗口）。
Opaque 窗口：无 `WS_EX_LAYERED`，`WM_PAINT` 路径 present 用 DIB + `BitBlt`；可嵌子控件。
`OverlayWindow` trait 面不变（poll_event/present/position/screen_size），事件队列/窗口类复用。

### D2 — Win32 子控件 = 输入基座（自绘 IME 明确不做）

- **EDIT**: 文本（label/unit/条件/页面名/搜索）。中文输入、光标、选择、剪贴板系统白给。
- **COMBOBOX**: 枚举下拉（format/arrange/kind）与 Target 变量目录（数据源 = kernel 变量目录，现成）。
- 数字 = EDIT + ± 步进按钮；开关 = 自绘方块（已有）；颜色 v1 = 预置色板循环点击。
- 子控件生命周期归控件封装层（按需 CreateWindowW，位置随布局刷新，`WM_COMMAND`/`EN_CHANGE`
  经 WNDPROC 进既有事件队列 → chrome 泵消费）。
- 字体: UI 层建 GDI `HFONT`（按档位），`WM_SETFONT` 注入子控件；自绘文字继续用 swash `LoadedFont` 多档。
- 备案（不做）: 自绘文本编辑 + IMM32 — 重造输入法轮子，中文候选交互风险不可控，否决。

### D3 — 原生 Inspector：propsSchema 驱动的侧栏属性区

- 选中组件 → 侧栏下半区切换为属性表单（与大纲互斥 tab，或上下分区可拖分界）。
- 表单 = 组件元数据 `props_schema`（现成，Rust 侧单一真相）逐项生成行：label + 控件。
- 外加通用行: id（改名）、启用开关、显示条件。
- 改值 → `UpdateComponent`（入单一撤销栈）；**文本失焦/回车才提交**（每键一撤销 = 栈污染）。
- 无选中 = 页面属性（页名/padding/字号/激活策略）。

### D4 — 编辑命令面与镜像推送退役（链路单一真相化）

Editor 全原生化后，`EditCommand` 只剩渲染线程内部消费者：
- 退役: `RequestKind::EditCommand` + `commands_edit::edit_command` + `UiCommand::Edit` IPC 链
  （form_dispatch 分支 / webui ipc / 前端 editApi）。
- 退役: `push_doc_event` 镜像推送（hud-edit-doc/selection/error 三键）+ bridge 对应订阅
  + 前端三监听。`EditCommand` 不再需要 serde（枚举转内部）。
- 保留: `begin_edit_session` invoke（MainForm footer 入口）→ `UiCommand::BeginEditSession`；
  HUD_EDIT_SESSION 事件（bridge 只管 MainForm 隐退/恢复）。
- `end_edit_session` invoke 退役（悬浮条完成/放弃走渲染线程直调 `on_end_edit_session`）；
  App.tsx 的自动提交收尾（托盘开始等）已是 UiCommand 直达，不受影响。

### D5 — 组件库缩略图 + 搜索

- 离屏小样: 注册表条目用 default_props 经组件工厂构造一次，`draw` 到 128×56 离屏 PixCanvas，
  会话开始时预渲染缓存（静态小样，数据不进缩略图）。
- 条目布局升级: 左缩略图 + 右名称（行高 ~64）；分组标题不变。
- 搜索: 侧栏组件库头部一个 EDIT（D2），按显示名前缀过滤（纯函数，可黑盒测试）。
- 构造失败的组件（props 依赖缺席）→ 兜底色块 + 名称（不静默消失）。

### D6 — 页面管理原生化

- tab 行尾「＋」= 新建页：弹原生命名输入（小 Opaque 窗口 + EDIT，回车确认）→ `UpsertPage`。
- tab 右键 = 画布内菜单复用（EditMenu 绘制/命中机制移植到侧栏窗口）: 复制/删除/恢复出厂。
- 命令复用（已存在）: `UpsertPage`/`DeletePage`/`UpdatePage`，全部入撤销栈。
